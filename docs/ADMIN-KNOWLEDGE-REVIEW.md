# 管理后台与知识库检查记录

检查日期：2026-10-12。结论来自当前代码、真实部署的 BGE-M3、隔离 MySQL 数据库及受控 HTTP 测试应用，不代表所有业务路径或第三方依赖均已通过渗透测试。

## 知识库是否在使用 BGE-M3

**模型可用，但现有知识库没有自动切换到 BGE-M3。**

- 已部署实例为 `bge-m3`，运行状态 `RUNNING`，Provider 已注册。
- 实测临时知识库执行了真实模型调用、1024 维向量生成、Qdrant 建索引、向量检索和重新索引。跨用户检索被拒绝；测试数据已清理。
- 当前未设置 BGE-M3 为默认 Embedding；现有 1 个 native 知识库未绑定托管模型。它的环境配置仍指向 `text-embedding-3-small`、1536 维。本次未验证该远程服务的可用性。
- 原有知识库保持原文和绑定不变。本次没有替用户迁移或重新索引现有资料。

操作路径：

1. **管理后台 → 知识库模型 → BGE-M3 → 设为默认**：只影响随后新建的知识库。
2. **知识库 → 检索测试 → 选择已有知识库 → 选择 BGE-M3 → 绑定模型 → 重新索引**：显式迁移已有知识库。
3. 索引显示就绪后再测试“向量”或“混合”检索。不同模型的向量空间不混用。

相关代码：`ManagedEmbeddingService`、`EmbeddingService`、`KnowledgeIndexService`、`NativeRetrievalService`、`KnowledgeEmbeddingSelector.vue`。

## 配置保存语义

- 系统配置**不是自动保存表单**，编辑后需要点击“保存”。取消或刷新不会保存未提交的草稿，页面已明确说明。
- 保存失败时对话框和输入保留；并发冲突返回 409，要求重新加载后再编辑，不静默覆盖。
- MySQL 是配置主存储。已有 `system_settings` Seed 只补缺失项，本次继续保留这一行为。
- 真实服务重启前后核对了系统设置、供应商、路由、用户角色/余额/验证状态和知识库的内容摘要，全部一致。
- 自动初始化新增 `bootstrap_seed_state` 与用户 `auth_version`。不要求管理员编辑 `.env`。
- 此次校验保留已有业务数据，临时测试数据库与测试知识库已清理。

## 待完成的加固项

1. **供应商密钥存储**：`provider_api_keys.api_key` 仍为明文，管理员列表响应也包含明文供现有查看功能使用。需独立的兼容迁移、加密存储和按需读取设计；本次没有修改或轮换现有密钥。
2. **用户彻底删除**：现有删除操作只清理账单、聊天、API Key 和用户记录，不覆盖全部 Agent、工作流、知识库及派生向量。已保证当前删除步骤的事务性、删除后的认证失效，但尚未实现完整资源清理与外部存储清理任务。
3. **环境密钥回退**：供应商池会合并环境变量中的密钥。删除数据库中的某条密钥不等于停用相同的环境密钥，也不等于在供应商侧撤销它。
4. **多副本缓存与审计**：目前 Compose 单后端实例的保存和刷新验证通过；多个后端副本尚无跨进程配置缓存失效广播。通用后台修改也缺统一、持久化的操作者审计记录。
5. **备份恢复与长期作业**：事务与 Seed 不能替代备份。未演练整个生产库/向量库灾难恢复，也未做大量文档、长时间 CPU 索引或多节点并发的压力测试。索引超时后应查询状态，不应直接重复提交。

- 真实 BGE-M3 与 Qdrant：建索引、语义检索、重新索引、跨用户拒绝、清理后原有业务摘要不变。
- TypeScript/Vue 类型检查与改动文件的 `git diff --check`。

前端回归为实际函数与源码契约检查，未使用真实管理员账户进行浏览器全流程操作；HTTP 权限检查使用受控测试身份，不涉及现有账户凭证。
