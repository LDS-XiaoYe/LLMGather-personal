# Agent 调用页：回放与过程展示修复

## 行为调整

- 执行中的 Run 与查看中的 Run 分离。SSE 校验 Agent / Run；历史请求、执行回调校验请求代次、账户与后端地址，迟到结果不覆盖新选择。
- 历史重跑改为“重跑任务”：填入所选任务与已记录图片，默认新会话，人工检查后按当前已保存 Agent 配置执行。继续历史会话是单独选项，父 Run 在清空展示状态前捕获。
- 回放明确为历史自动浏览。上一步、下一步、暂停与跟随实时分离；填入步骤输入不宣称节点恢复。断开 SSE 不宣称服务端任务已取消。
- 时间线展示真实步骤顺序、失败尝试与重试，不再以固定五阶段推断 LLM 是否被跳过。
- 兼容旧版聚合工具结果，子工具失败在卡片与异常统计中体现。旧版召回数量兼容解析；未知值显示“未记录”，不伪造 0。
- 单次耗时、Token 与历史统计分区，不把账户账单当成本次费用。比较由用户选择另一条同 Agent 记录，区分任务输入、模型、历史提示词、技能 ID、工作流 ID 和步骤状态。
- 配置、消息、工具与记忆展示只来自真实记录；游标之前没有发生的记忆步骤不显示。旧历史缺失配置不会用当前草稿补齐。

## 组件与布局

`frontend/src/components/agent/AgentRunTrace.vue` 集中负责过程/历史面板；`frontend/src/utils/agent-trace.ts` 集中处理历史格式、快照、比较、来源和工具状态。

调用页保留任务、图片、工具结果、输出和评测入口。桌面双栏；内容宽度不足时切换“任务与结果 / 过程与历史”，无需滚到长输出后寻找追踪。调用区提供 Agent 选择入口。比较按面板宽度最多两列，技术数据默认折叠；真实节点具有选中语义，游标通过 aria-live 通报。Enter 换行，Ctrl/Command+Enter 提交，并排除输入法组合输入。

## 后端兼容

沿用已有接口与数据库结构。运行配置写入 context_pack.metadata.runtimeSnapshot，模型调用请求写入 llm_completion.metadata.requestSnapshot，结束步骤时合并元数据，保留已记录请求。

`backend/src/agents/trace-snapshot.ts` 在序列化前逐项脱敏，控制快照不超过 32000 UTF-8 字节，为 MySQL TEXT 的其他元数据留出空间。超限不截断 JSON、不阻断业务，仅标记完整配置/消息未保存。工作流直达路径等没有该快照的记录仍显示未记录。

本次没有引入 checkpoint 恢复和服务端取消协议；页面如实区分历史浏览、准备新任务与断开连接。

## 调用页补充修复（2026-10-13）

- 输出区和统计明确属于“所选运行”；执行中显示“生成中”，不把历史输出或流式片段称作本次最终结果。
- 工具输出格式化保留完整 JSON，不再抽取 result/stdout 后丢掉 stderr、日志、退出码等诊断信息。旧聚合工具结果中的 0/false 保留，缺失耗时显示“未记录”，错误单独展示。
- 复制输出、重跑回填与步骤输入回填恢复即时反馈；重复复制同一输出也会提示。连接中断与未收到结束状态使用明确通知，不宣称后台取消或执行成功。
